02

Roles and boundaries

Proposed responsibility split

This is a working allocation pending confirmation by Röbel, Komma/Meld/Kair, Stadtstack and each municipality. Technical stewardship does not grant publication or municipal authority.

Röbel is the proposed technical product steward for the public community experience: ordinary posts, signed Discussions, Topics, the one Civic Journey view, Public Mecky, and Mitmachen rendering.

Stadtstack maintains the municipality-neutral contracts and reference implementation. The municipality's designated owner controls source admission, publication policy, Case authority and every Authority transition.

City-approved source Adapters capture exact council records and rights-permitted local reporting without conflating their authority. The responsible municipal department owns administration work; openDesk may host or exchange the task record.

Meld/Kair is a proposed consent-scoped session integration. If agreed, a dedicated connection would need to preserve exact context references, consent, pseudonymisation, retention, provenance and review before any public-safe contribution.

No single project does this alone. Their contracts meet at an eligibility-gated Public knowledge projection and a stable Topic/Case reference, not by merging identities, databases, or authority.

03

Standards

Where OParl, RIS and local news fit

OParl is an interchange specification; a Ratsinformationssystem is a source and publication surface; local reporting is editorial. Source-specific Adapters preserve those distinctions.

Reviewed public sources are one of three independent inbound seams into the Civic Journey.

The Adapter must preserve the exact source system, originating identifier, publisher, municipality, record kind, publication state, correction history, rights profile and source owner. A meeting, agenda item, paper, minutes and final decision have different status; OParl transport does not make them interchangeable or create a new official system of record.

A human Reviewed source admission then decides whether that exact capture can enter a source-specific Reviewed source projection. Public Mecky can cite that projection without asking the administration to approve every generated sentence. For local news, review does not create republication rights: the public projection defaults to a citation, digest, metadata and only a rights-permitted excerpt.

Cross-municipality matching is a separate discovery projection. Similarity can suggest related Topics, but it cannot merge Cases, infer consent, or make one city's record authoritative for another.

04

Delivery

One shared stream, several clients

Charlie's cross-client goal remains central. Stadtstack proposes a replayable REST/cursor feed as the canonical history, with MCP as a bounded agent interface over the same projection and Nostr as an optional signed public mirror.

One eligibility-gated Public knowledge projection feeds three bounded surfaces: REST/cursor for replay, MCP for agent reads, and Nostr for permanently public signed exchange.

The REST surface answers “what changed since this cursor?” with deterministic, bounded pages and explicit correction records. MCP can expose normalized, read-only municipal resources for bodies, meetings, agenda items, papers and decisions, plus a Topic, reviewed source, Case projection, citation, or status explanation over the same version and digest.

MCP cannot admit a Case, attest a review, send an openDesk request, publish a Citizen Brief, start Mitmachen, cast a formal vote, sign a Safe transaction, or move treasury funds. Whether subscriptions or notifications belong in the first shared prototype is a jointly deferred decision; if added, they must not create a second source of truth.

06

Scoping

Three interoperability slices

These slices test Charlie's enrichment hypothesis independently from the Röbel browser tracer. Both tracks may run in parallel and meet at the same reviewed projection.

Slice 01Council context fixture

Map exact meeting, agenda-item, paper, minutes and decision records while preserving source IDs, record kinds, publication state, rights and correction lineage.

Slice 02Consented context session

Test whether one synthetic bundle can reference that exact context, remain private by default, and yield one reviewed public derivative under distinct publication and Case-citation purposes.

Slice 03Feed + clients

Serve deterministic content-minimal changes, bounded MCP reads and a Röbel consumer over the same version and digest. Add Nostr only after an independent permanent-public gate.

07

Before committing

Open questions

Worth resolving before accepting the integration contract or presenting a live capability.

Consent and identity

What exactly does a Meld/Kair session consent permit: retrieval, public exchange, Case citation, or only private review? A session pseudonym must not become a Röbel member identity without a separate link receipt.

Technical and licensing assumptions

Confirm the bundle wire format, capture location, models, retention/deletion, software and data licenses, and programme ownership with the collaborator before implementation.

Source legality and correction

For each OParl/RIS or local-news Adapter, confirm terms of use, source owner, capture rights, update cadence, withdrawal, and correction behavior.

Feed governance

Which actor can review, correct, withdraw, or publish a projection entry? The feed can be public and agent-readable without granting authority to a relay, MCP server, or model.

Cross-municipality discovery

Similarity must remain opt-in, public-safe discovery. It cannot merge Cases, copy session content, infer consent, or make another municipality's record authoritative.

08

Next step

Suggested next step

First, confirm this reading with Charlie, Max and the Komma/Meld/Kair owners: the proposed content-enrichment sequence, Kair's actual interface, ownership, consent purposes, hosting, licensing, and the first prototype audience.

In parallel, continue the Röbel staging tracer and prepare one exact council-context fixture. Subject to municipality approval and source rights, the intended first real interoperability target is then an exact Strausberg RIS capture. Test one synthetic consent-scoped session against that context, then expose the reviewed derivative through the shared feed, bounded MCP and a Röbel consumer. Nostr remains limited to independently permanent-public artifacts.

The essence is a context enrichment network: council records can ground a consented conversation, and a reviewed derivative can help the next community—without becoming a decision or authority by transport alone.
