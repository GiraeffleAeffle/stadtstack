01 / The civic information loop

Context in, public learning back

The network is not a one-way import. Existing municipal records can ground a session or discussion. A resulting proposal can enter administration work. Once the municipality publishes an outcome under its own policy, that update becomes part of the public context for the next conversation.

02

Three contributors

Three parts of one project

The first brief described three complementary contributions. The interfaces will be refined together once the Kair code and a test device are available.

Charlie Fisher / Komma Systems / Kair contributes the session layer: software that can capture and organise the context of a group conversation and produce a structured bundle for permitted reuse.

Max Brych / Röbel App contributes the public community layer: ordinary posts, signed discussions, pro/contra views, proposals and the first resident-facing journey tracer.

Maximilian Stahl / Stadtstack contributes municipality-neutral source adapters, shared Civic Case contracts, administration and openDesk exchange, public projections, identity and governance boundaries. Strausberg remains one separate project context.

The municipality remains responsible for official records, publication and decisions. Technical stewardship by any of the three contributors does not grant municipal authority.

Shared seam

Every component can refer to the same topic and exact source versions without sharing one database or identity system.

One visible journey

03

Municipal context

A reusable layer around OParl

The goal is not a private fork called “OParl 2.” It is a Municipal Civic Context Exchange: a strict OParl-compatible view for official parliamentary publications, plus a broader linked view for reviewed civic context.

OParl makes already-public parliamentary information readable across systems. It is not a write workflow for a Kair session, community proposal or openDesk task.

A reviewed Kair artifact or administration response may become a municipal publication candidate. The same municipality may operate Kair, openDesk and the publication service, but it must still record which designated publication role or governed service accepted the exact version under its publication policy. Only then is it an official municipal publication that can be mapped into the appropriate RIS/OParl-compatible objects.

The broader exchange can also link reviewed discussions, sources, Citizen Briefs and status updates without pretending that they are OParl objects. Public Mecky and other agents read these records with citations and visible status.

Corrections, withdrawals and superseding publications remain explicit events, so other municipalities and agents can see not only what exists but what changed.

Strict view

OParl-compatible publication

Official bodies, meetings, agenda items, papers, files and published results keep their standard meaning and official publisher.

Broader view

Municipal Civic Context

Reviewed community artifacts and administration updates stay linked, typed and clearly below official authority until published.

Kair and openDesk can help create and route the material inside a municipality's own environment. A governed municipal publication action creates the official publication. The exchange makes both the relationship and the difference visible. Closing the loop without blurring authority
04

Delivery

One shared stream, several clients

A correction-aware update stream lets municipal portals, resident-facing apps such as Röbel, other municipalities, residents and agents follow the same public context without scraping every source separately.

One eligibility-gated Public knowledge projection feeds three bounded surfaces: REST/cursor for replay, MCP for agent reads, and Nostr for permanently public signed exchange.

The REST surface answers “what changed since this cursor?” with deterministic pages and explicit correction records. MCP exposes read-only resources for published municipal records and the broader reviewed civic context over the same version and digest.

MCP cannot admit a Case, attest a review, send an openDesk request, publish a Citizen Brief, start Mitmachen, cast a formal vote, sign a Safe transaction, or move treasury funds. Whether subscriptions or notifications belong in the first shared prototype is a jointly deferred decision; if added, they must not create a second source of truth.

05

Self-hosted Kair

Software for hardware a community controls

The current shared direction is that the Kair code becomes available for local operators to install and test on hardware they buy and operate themselves. This is a future trial track, not a dependency of the current Röbel/Stadtstack product work.

Deployment model

Locally operated

The comparison to MeshCore or Meshtastic describes the self-owned deployment ethos only; it is not a claim of protocol compatibility.

This is a working deployment hypothesis until repository access and the first hardware installation confirm it. Kair remains independent software; Stadtstack defines only the exchange boundary needed to reference sources, consent and reviewed output. Any municipality can choose its own hosting and operational model.

06

Three coordinated tracks

One shared boundary, three independent tracks

The first brief proposed a two-month infrastructure prototype targeting the end of October. That remains a historical scoping target and must be re-baselined once code access, hardware, participating municipalities and source scope are confirmed. The current Röbel/Stadtstack tracer does not wait for Kair.

Track 01 · shared protocolMunicipal Civic Context Exchange

Map one selected municipality's exact public source into a source-preserving context. Deliver reviewed public updates through a correction-aware feed, strict OParl-compatible view and broader linked civic-context view.

Track 02 · current product tracerRöbel + Stadtstack

Prove the resident journey now: ordinary post, discussion, pro/contra, cited Mecky, signed suggestion, Case, administration return, Citizen Brief and advisory participation. Kair remains optional here.

Track 03 · future municipal trialsKair runtime + compatible clients

After code, licence and device validation, test one consented bundle and the same exchange contract with a participating municipality and any compatible client. Röbel can be one client, never the required one.

Candidate Kair trial contexts — confirmation required: Herzogtum Lauenburg, Schleswig-Holstein (lead client NextLearning e.V., Berlin; local partner Landvorteil e.V., Ratzeburg; supported by Wirtschaftsförderungsgesellschaft Herzogtum Lauenburg mbH / WFL), and Ludwigslust-Parchim, Mecklenburg-Vorpommern (supported by the South West Mecklenburg Economic Development Agency). These are possible trial contexts, not commitments or protocol defaults. Closed-loop acceptance: carry one resident proposal into municipal administration work, return a reviewed response, issue a governed municipal publication, and observe the new version through the same feed and MCP interface.
07

Boundaries

Open questions

The prototype should answer these questions with executable evidence rather than assumptions.

Consent and identity

What exactly does a Meld/Kair session consent permit: retrieval, public exchange, Case citation, or only private review? A session pseudonym must not become a client member identity without a separate link receipt.

Code and device operation

Confirm repository access, licence, supported hardware, install, update, rollback, device identity, encryption, offline replay and operational support.

Source legality and correction

For each OParl/RIS or local-news Adapter, confirm terms of use, source owner, capture rights, update cadence, withdrawal, and correction behavior.

Publication authority

Which municipal role or governed publication service may turn an openDesk response or reviewed session artifact into an official publication, and which OParl-compatible kind and identifier should represent it? It may run beside Kair and openDesk in the same municipal environment.

Cross-municipality discovery

Similarity must remain opt-in, public-safe discovery. It cannot merge Cases, copy session content, infer consent, or make another municipality's record authoritative.

The essence is a civic learning loop: public records inform a conversation, the conversation can improve municipal work, and an authorized result returns as better public context for residents, municipalities and agents.
