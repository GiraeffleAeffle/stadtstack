# ADR 0037: Explicit Case selection for synthetic review

- **Status:** source implementation; staging activation pending
- **Date:** 2026-09-15

## Decision

The review listener may serve up to eight explicitly configured, already
admitted synthetic Cases in its municipality. `administrationReview.caseId`
remains the default. Optional `additionalCaseIds` names the others. Every Case
must open successfully before any listener binds; unknown Cases, duplicate IDs,
foreign municipalities and grants outside this list fail configuration.

The original `/v1/staging/administration/review` and `citizen-brief` routes keep
their original default. Additional Cases use
`/v1/staging/administration/cases/<encodeURIComponent(caseId)>/review` and
`citizen-brief`. Only canonical encodings are accepted: queries, raw-colon
aliases, double encoding and trailing slashes are rejected. Selecting a Case
never selects an actor or conveys authority. Each existing expiring credential
continues to bind one actor to exactly one Case. Admission tokens remain separate.

All Cases use the same durable owner, coordinator, registry and journal rules.
There is no additional database, writer, directory of private Cases or new civic
command. A confirmed Brief remains a separately typed public synthetic return;
pending drafts and private evidence remain excluded. The original admission
receipts are immutable, including after department work advances either Case.

This extends [ADR 0035](./0035-bind-administration-review-to-the-case-runtime.md)'s
single-Case routing choice. It does not change the SQLite schema or the existing
review-enabled store fingerprint. Adding a Case still requires its separately
authorized admission and explicit deployment configuration and grants. Release
changes retain the existing Operations upgrade, backup and preservation checks.
The source change alone grants no access and performs no live admission.

## Evidence

Two independently signed interoperability vectors are admitted through the
existing atomic writer. Real HTTP tests assign, draft and independently review
a package on the second Case; the first Case and both original receipts remain
identical. Cross-Case tokens, noncanonical routes and credential-bearing public
reads are rejected. Clean shutdown, restart and exact command retries preserve
both histories. The second vector is generated by Röbel's public APIs with
explicit offline wallet/NFT stubs; it represents no actual citizen or authority.
